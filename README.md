# 本地赛道计次裁决台

使用 **Python / FastAPI + 原生 HTML/CSS/JavaScript** 实现的本地赛道计次裁决工具，
无需外部数据库，所有数据只在本机处理。

## 一键启动（Docker Compose）

```bash
docker compose up --build
```

启动后在浏览器访问：

- **http://localhost:8000**

停止服务：

```bash
docker compose down
```

> 端口映射为宿主机 `8000` → 容器 `8000`，如被占用可修改
> [`docker-compose.yml`](docker-compose.yml) 中 `"8000:8000"` 的左侧端口。

## 不用 Docker 的本地运行方式

需要 Python 3.11+：

```bash
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

访问 http://localhost:8000 。

## 页面使用

1. **选手区**：录入 1～3 名编号互异的选手；为每人填写
   - 起点 → 中途门 的合格耗时闭区间
   - 中途门 → 终点 的合格耗时闭区间
   - 区间均为**正整数**秒（下限 ≤ 上限）。
2. **记录区**：录入至多 **40** 条感应记录，每条包含
   - 唯一字符串 ID
   - 选手编号
   - 门：起点 / 中途门 / 终点
   - 非负整数秒
   记录允许乱序录入，同一秒允许出现多条；可随时增删、清空或「载入示例」。
3. 任意输入修改后会自动重新计算（也可点「立即裁决」）。
4. 结果按选手列出：
   - 每一趟采纳的 **起点 → 中途门 → 终点** 三条记录 ID、秒数及两段耗时、整趟用时；
   - 该选手的**未采纳记录**；
   - 没有任何完整计次的选手明确显示 **零次**；
   - 输入非法时页面只展示错误清单，**不展示任何部分结果**，修正后自动重算。

## 裁决规则

- 一趟由同一选手的三条记录组成，顺序为 **起点 → 中途门 → 终点**；
- 两段耗时（中点秒−起点秒、终点秒−中点秒）都必须落在对应闭区间内；
- 同一选手的各趟**不得共用任何记录**；
- 后一趟的起点秒数必须**严格大于**前一趟的终点秒数；
- 其余无法参与任何完整趟次（或被更优方案舍弃）的读数列为「未采纳记录」。

对每名选手按以下优先级选择唯一方案：

1. **完整计次数最多**；
2. 计次数相同时，**各趟用时之和最短**（用时 = 终点秒 − 起点秒）；
3. 仍相同时，取**按计次时间顺序串接的记录 ID 序列字典序最小**的方案。

算法按候选趟次的终点时间排序，用带二分查找的动态规划（加权区间调度）求最优解，
记录乱序不影响结果。

## HTTP 接口

- `GET /`：裁决页面
- `POST /api/judge`：请求/响应均为 JSON。

请求示例：

```json
{
  "runners": [
    {"number": 1, "seg1": {"lo": 4, "hi": 6}, "seg2": {"lo": 6, "hi": 8}}
  ],
  "records": [
    {"id": "s", "runner": 1, "gate": "start",  "second": 0},
    {"id": "m", "runner": 1, "gate": "mid",    "second": 5},
    {"id": "f", "runner": 1, "gate": "finish", "second": 12}
  ]
}
```

合法时返回 `200` 与每名选手的计次明细；非法时返回 `422` 及全部错误信息
（`{"ok": false, "errors": [...]}`），不返回部分结果。
